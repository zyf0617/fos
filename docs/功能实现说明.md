## 2. 从启动到用户态

源码：`src/kernel/boot/entry.S`、`boot/start.c`、`main.c`、`proc/proc.c`、`trap/trampoline.S`。

1. OpenSBI 将控制权交给内核入口，保存实际启动 hart，设置本核启动栈。
2. 启动核初始化串口、物理页池、mmap 节点池、内核页表和中断控制；启用 Aegis 时初始化组策略与审计环。
3. 通过 SBI HSM 启动辅助 hart；每个 hart 切换自己的 `satp` 并设置本地定时事件。
4. 启动核构造首进程：分配 trapframe、用户页表、1 个代码页和 1 个初始栈页。用户镜像由构建过程转换成内核可引用的字节数组。
5. 设置用户入口、栈顶及首次内核上下文，经 `swtch` → `trap_user_return` → trampoline 返回用户态。

实际启动核由 `boot_hartid` 决定，首进程、UART 接收归属和全局 ticks 的更新保持一致。辅助 hart 当前留在内核，不参与用户进程调度。双 hart 启动不能等同于多用户进程并行。

## 3. 物理内存、锁与 Sv39

### 3.1 物理页的所有权

源码：`mem/pmem.c`、`lock/spinlock.c`。

可分配内存分为内核页池和用户页池。空闲页的首部保存下一页指针，分配在池锁内摘取页并更新计数，随后清零；回收检查页对齐、所属区域和所有权位，防止重复释放。分配失败返回 NULL，由上层决定回滚或停止用户程序。

锁使用原子操作与内存屏障；本核用 `push_off/pop_off` 保存中断关闭的嵌套深度。最后一次释放恢复进入最外层临界区前的中断状态。

### 3.2 地址转换与权限

源码：`mem/kvm.c`、`mem/type.h`。

Sv39 用三级 512 项页表表示 4 KiB 页。页表叶项的 R/W/X/U 位决定读、写、取指和用户态访问权限。代码页为 RXU，用户堆栈为 RWU；trapframe 和 trampoline 没有 U 位。

`vm_getpte` 查找最低层项，按需建立中间页；`vm_mappages` 先检查整个请求范围，再建立映射，失败撤销本次新建项。`vm_unmappages` 清除叶项，执行 TLB 失效后才归还物理页；其底层契约保留中间表，用户内存层负责额外清理空表。

### 3.3 多页修改为什么需要事务

源码：`mem/uvm.c` 的 `allocate_range`。

一次 brk、扩栈或 mmap 可能需要多个数据页和多个页表页。前几次分配成功不能代表整个操作成功。

本实现先在临时页表取得全部资源；Aegis 开启时，首先预留整批用户页预算。任何一步失败，都销毁临时树并归还预算。完全成功后通过 `vm_merge_user` 无分配地合并进目标树，再释放临时树剩余表页。

失败承诺包括：原 PTE 树、堆顶、栈页数、mmap 链、节点数、两个页池的计数和组预算保持不变。逐分配点注入 OOM 验证这一点，不仅检查最终返回值。

## 4. 用户内存服务

源码：`mem/uvm.c`、`mem/mmap.c`、`syscall/sysfunc.c`。

| 功能 | 具体做法 | 失败和边界 |
| --- | --- | --- |
| copyin / copyout | 逐页找叶项并验证 V/U/R 或 V/U/W，按页片段复制 | 后页失败允许留下已经复制的前缀；零长度不访问指针 |
| copyinstr | 逐页验证和逐字节寻找 NUL | 不读取 NUL 之后的页；没有终止符或上限为 0 时失败 |
| brk | 字节级记录堆顶，用页向上取整计算增减区间 | 页内变化不增减物理页；不得下穿初始堆或进入 mmap 区 |
| 自动扩栈 | 仅处理合法栈区的 load/store 缺页，一次补齐旧栈底到故障页之间的全部页面 | 已有页权限错误及取指异常不扩栈；配额/OOM 失败停止用户程序 |
| mmap | 按地址排序的已分配区间链；自动首次适配或固定地址；同权限相邻区间合并 | 重叠、对齐、权限、资源不足时不发布部分状态 |
| munmap | 先确认全部范围覆盖，提前保留中段拆分节点，再解除和更新链 | 含空洞或节点不足整体失败；可跨权限区间裁剪 |
| 空页表回收 | 缩堆/munmap 后递归检查本次范围涉及的分支，回收已空的中间表 | 保留根和非空相邻分支；先解除父项、刷新 TLB，再释放表页 |

mmap 的元数据来自带锁的固定 256 节点池。节点唯一属于空闲池、临时操作或进程链；同一节点不能被两个 hart 同时持有。相关测试检查耗尽、复用及并发唯一所有权。

## 5. 系统调用与陷阱

源码：`syscall/syscall.c`、`syscall/sysfunc.c`、`trap/trap_user.c`、`src/user/syscall_arch.h`。

用户封装把编号放在 a7，最多 6 个参数放在 a0–a5，执行 ecall。trampoline 保存完整整数现场并切到内核页表和内核栈。处理器只在 ecall 路径把用户 epc 加 4；成功修复栈缺页时保留原 epc 重试。

| 编号 | 服务 | 返回语义 |
| --- | --- | --- |
| 0 | helloworld | 成功 0 |
| 1 | copyin | 成功 0，失败 -1 |
| 2 | copyout | 成功写出 5 个整数并返回 5，失败 -1 |
| 3 | copyinstr | 成功 0，失败 -1 |
| 4 | brk | 查询或修改成功返回字节堆顶，失败 -1 |
| 5 | mmap | 成功返回地址，失败 0 |
| 6 | munmap | 成功 0，失败 -1 |
| 7 | printf | 返回输出长度，失败 -1；用户内容按字符串数据输出 |

完整 64 位调用号先做边界检查，不先截断成 32 位。未知调用返回 -1，内核继续。长度等参数也先检查完整宽度及溢出，再缩窄；用户 printf 上限为 127 字节加 NUL，用户内容不会成为内核格式串。

无法恢复的用户错误经 `proc_return` 切回 CPU 上下文，释放用户页表和动态资源；不再返回故障进程。内核继续接收时钟和 UART 中断。

## 6. Agent Group 与共享资源预算

源码：`agent/agent.c`、`agent/mod.h`、`proc/type.h`、`mem/uvm.c`。

### 6.1 目前实现的数据模型

`agent_group_t` 保存组号、用户数据页上限/占用、成员数上限/当前数、syscall 允许集合、预留峰值、配额/权限拒绝次数、物理分配失败事务数及组锁。`proc_t` 增加 `agent` 指针与该进程的收费页数。普通进程的 `agent=NULL`。

`agent_attach` 在进程独占上下文执行：拒绝重复入组，检查成员数和已有数据页能否纳入预算，再发布成员关系。`agent_detach` 归还该成员的剩余收费，并清空归属；重复 detach 无操作。组对象由内核持有，必须比成员活得更久。

默认课程启动组采用64个用户页、1个成员、全部8个课程服务权限；开启生命周期扩展后为64页、4成员、13个服务权限。专用测试组采用 4 页、1 个成员，并禁止 copyout；这是便于演示的固定内核策略，不是已经完成用户态策略管理器。

`agent_snapshot` 在组锁内复制策略、当前占用、预留峰值和拒绝次数，避免多个字段来自不同时刻。`agent_restrict` 是内核可信管理接口，只能减少权限集合、页数上限和成员数上限；新上限不得低于当前占用，失败保留全部策略。此前已经通过检查的在途调用不被追溯撤销。该接口没有用户态ABI，尚不构成agentctl。

### 6.2 内存收费路径

```text
用户 brk / mmap / 栈缺页
    → 检查地址、长度、既有映射
    → agent_charge：组锁内整批预留页数
    → 临时树申请用户页和页表页
        ├─ 失败：销毁临时树 + agent_uncharge
        └─ 成功：合并页表 + 发布对应元数据

缩堆 / munmap成功 → 释放数据页和空表 → agent_uncharge
进程故障退出 → 销毁剩余用户映射 → agent_detach归还剩余收费
```

代码页和初始栈页在入组时合计收费 2 页。此后 heap、stack、mmap 使用同一组预算；同页内调整 brk 不重复收费。多个成员共用一个计数，因此不能靠换成员分摊绕过上限。

当前占用包含已提交页面和事务尚未完成的预留。失败归还当前占用，但预留峰值与拒绝次数保留历史，不应被误解为当前实际映射量。双hart测试先用屏障让两个内核成员同时申请唯一预算，断言恰好一个成功，再各竞争1000轮，检查无双重持有、峰值始终为1、结束后预算与页池全部恢复。这验证真实并行内核调用的计数机制，该并行测试本身不运行用户程序；真实用户fork协作运行的证据见6.4节。

预算单位为用户数据页。trapframe、页表页和其他内核元数据仍由内核资源池管理，尚无每组内核内存限额。因此目前可表述为“用户数据页隔离原型”，不能称为完整内存 DoS 防护。

### 6.3 资源复制与组继承准备

源码：`proc/proc.c` 的 `proc_clone_resources`、`proc_release_resources`；测试：`proc/clone_test.c`。

调用者稳定持有源和全零目标，保证源不被其他 hart 同时运行或修改。资源复制先统计实际用户叶页；源已入组时，复用 `agent_attach` 在组锁内同时检查并预留一个成员和全部数据页，然后才申请 trapframe、页表、独立 mmap 节点及用户页。源没有组时，目标保持普通进程。

目标共享同一组对象，因此收紧组策略会同时作用于源与目标。用户数据页、trapframe 和 mmap 节点独占，trampoline 共享。用户寄存器与 PC/SP 被复制，目标 a0 置 0；内核 satp、栈、trap 入口和 hart 字段清零，未来运行入口负责重填。目标内核栈和上下文保持零，不能直接调度。

任何失败都先销毁目标地址空间，再退还全部组预留和成员名额、释放 trapframe/节点并清零目标。首进程故障清理也复用该释放函数；预映射内核栈仍由运行层持有。失败尝试会保留预留峰值与 attach/detach 审计，attach 表示资源成员预留，不代表子进程已经运行；复制拒绝沿用 attach 失败语义，不计入 heap/mmap/stack 的 quota_denied 或 allocation_failed 统计。

QEMU 测试在8页源布局上逐页比较内容和权限，分别修改双方验证独立性，并扫描19个物理分配失败点。还覆盖两段 mmap 复制到第二节点时池耗尽、页预算不足、成员名额不足、成功后收紧共享策略、重复清理及最终页池/节点池/组计数恢复。每次物理失败后核对源页表和用户内容摘要。

这是fork的资源准备层，本接口本身不发布可运行任务；可选生命周期扩展在此基础上接入实际fork、等待和退出。详细顺序见 [后续开发计划](后续开发计划.md)。

### 6.4 可选的协作式进程生命周期

源码：`proc/lifecycle.c`、`proc/proc.c`、`mem/kvm.c`、`syscall/syscall.c`、`trap/trap_user.c`。入口：`PROC_LIFECYCLE=1`，默认0保持课程单用户与0–7 ABI。该实现属于项目预研，课程Lab6尚未发布。

4个固定槽分别使用独立的预映射内核栈，相邻页保持未映射，复用时清零栈。槽保存父关系、单调PID、状态和64位退出状态；只有实际启动hart访问进程表，关中断且不持锁跨越切换。运行路径为 `RUNNABLE → RUNNING → RUNNABLE/WAITING/ZOMBIE`，默认协作模式在用户yield、wait或退出时切回CPU上下文；额外开启`PROC_PREEMPT=1`后，用户timer可触发RR抢占，具体见6.5节。

fork通过M1接口取得独立资源，随后设置私有内核栈和首次运行上下文，最后发布RUNNABLE；父得到正PID、子得到0。整数寄存器由现有trampoline保存，尚不保存浮点/向量现场，返回用户态显式关闭FS/VS；测试确认浮点指令触发用户故障，避免跨任务共享未保存状态。

| 扩展号 | 服务 | 返回及失败行为 |
| --- | --- | --- |
| 8 | fork() | 父返回正PID、子0；槽位、PID、组预算或物理资源不足时-1 |
| 9 | exit(status64) | 不返回，保存完整64位退出状态；用户故障使用-1 |
| 10 | wait(status64指针) | 等待任意直接子进程并返回PID；0忽略状态；无子进程-1；坏指针保留退出记录供重试，失败可留下跨页复制前缀 |
| 11 | yield() | 让出执行，未来恢复后返回0 |
| 12 | getpid() | 返回当前PID，首进程为0 |

退出先标记ZOMBIE并切回CPU栈；调度器清空cpu.proc后才销毁地址空间、trapframe和节点，归还组数据页与成员名额。僵尸只占退出记录及槽位，wait复制成功后释放槽。父进程退出时清空子任务的父指针：僵尸自动释放槽，活跃孤儿继续运行并退出时自动回收；孤儿仍能fork/wait。这是本项目的有界原型语义，没有POSIX收养/信号、exec、SMP迁移或对象权限。

新增调用仍经过统一组权限检查。专门测试实际拒绝fork权限、超过共享页预算和超过成员上限；不是只测试内部入组函数。退出事件使用kind=8，旧事件编号保留；exit不返回，因此没有kind=3调用完成事件。fork的attach拒绝和复制OOM继续沿用M1统计语义，不混入heap/mmap/stack计数。

验收与复现见 [生命周期验收](PROCESS_VALIDATION.md)，包含四种保护/审计配置、真实fork逐分配点失败、等待坏指针重试、子故障、槽位耗尽、重复复用、父退出与孤儿继续fork/wait。

借鉴[cgroup事件分类](https://docs.kernel.org/admin-guide/cgroup-v2.html)，将 `quota_denied` 与 `allocation_failed` 分开：前者是组预算不够，后者是预算已预留、随后临时根/用户页/中间表分配失败。失败事务先回滚再增加计数和记录阶段。没有Linux回收或OOM killer，不使用其OOM事件作为同义名称。无效请求、mmap节点不足不计入该物理分配失败计数。

### 6.5 用户态timer抢占与RR基线

源码：`trap/trap_user.c` → `proc_timer_tick()` → `suspend()` → CPU调度栈。`PROC_PREEMPT=1`要求`PROC_LIFECYCLE=1`，两者默认均关闭。

用户中断进入trampoline时已保存全部整数现场，handler保存epc。timer分支先更新时钟并释放锁，再给当前任务累计一个用户timer样本；有其他RUNNABLE任务时，将当前任务设RUNNABLE并切回调度栈，按槽循环选择下一个。只有当前任务可运行时不进行自切换。恢复后重设用户sepc、stvec、sstatus、satp，timer不会像ecall那样推进epc。

所有切换仍检查实际启动hart、SIE关闭、noff=0和RUNNING状态。系统调用、内核trap和锁临界区不抢占，辅助hart不调度用户任务。名义周期沿用平台100ms时钟，内核处理会延后交付，主动yield后的任务继承剩余周期；没有每次dispatch重新获得完整时间片或硬实时保证。

任务退出时输出dispatch数、用户timer样本数和实际抢占数。这些数用于确认发生过切换，不能当作精确CPU运行时间、组预算或公平性指标。两个子任务使用不同的寄存器模式，纯CPU循环中没有ecall/yield；开启抢占的四配置下，两者在任意一方结束前均已启动，且各至少抢占2次。相同用户镜像关闭抢占时串行，构成功能负对照。原始日志、摘要和复现方式见[RR验收](RR_VALIDATION.md)。

## 7. Capability 原型与审计

### 7.1 在内核入口拒绝服务

调用路径：`syscall()` → 64 位编号验证 → `agent_allowed()` → 服务函数 → 审计。

默认允许集合为8位syscall mask；生命周期构建扩为13位，新增调用沿用同一检查。拒绝时服务函数完全不执行；mmap 保持失败 0 的 ABI，其他服务返回 -1。测试以禁止 copyout 为例：用户缓冲区事先填入 7，拒绝后仍全为 7，而允许的 copyin 仍能执行。

这是按服务分类的粗粒度权限门禁，属于架构中 capability 方向的第一阶段。它尚不是可委托的对象能力系统，也不具备文件路径、设备对象、exec 或网络权限。未来应在相应服务存在后增加资源对象和权限继承语义。

### 7.2 有界审计

审计记录包含：全局序号、原始 time ticks、group、pid、事件类型、详情、成功/失败和组页数快照。时间戳不是墙上时钟；按平台 timebase 才能换算时长。事件类型为：

| kind | 意义 | detail |
| --- | --- | --- |
| 1 | 成员入组 | 初始收费页数 |
| 2 | 成员移除 | 0 |
| 3 | syscall 完成 | 完整调用号 |
| 4 | 权限拒绝 | 调用号 |
| 5 | 内存预算拒绝 | 请求页数 |
| 6 | 用户故障/扩栈失败 | scause |
| 7 | 事务物理分配失败 | 1临时根、2用户数据、3中间页表；回滚后记录 |
| 8 | 生命周期扩展退出 | 0，不记录用户提供的退出状态 |

固定环最多保留 64 条，满后覆盖最旧记录；读取者以序号续读，接口返回本次可检测的丢失数量。热路径不分配、不打印，不保存用户字符串、指针或 brk/mmap 返回地址；服务结果被归一为成功 0 / 失败 -1。组页数是记录时的快照，尚不是跨核资源修改的完整事务日志。

组锁与审计锁分别保护各自状态，记录前释放组锁；串口导出在审计锁外执行。目前日志在故障清理后导出，持续运行时只能由内核读取接口获取，用户态 trace 工具尚未接入。它是可观测性原型，不承诺永久保存或抗篡改审计。

`AEGIS_AUDIT=0` 不分配事件环，记录接口无操作，读取返回0且丢失数为0；权限与预算检查、资源快照和拒绝计数继续工作。默认 `AEGIS_AUDIT=AEGIS`，可以独立比较采集成本。策略收紧目前未作为单独事件导出，完整管理审计仍待后续接口设计。

借鉴[内核事件过滤](https://docs.kernel.org/trace/events.html#event-filtering)，新增 `AEGIS_AUDIT_SUCCESS=0`：只过滤kind=3且结果为0的完成事件，在取组快照、入环前返回。拒绝、未知服务失败、故障、分配失败和生命周期保留。过滤不分配序号，不计作lost；成功洪泛不会覆盖既有拒绝，但失败洪泛仍会覆盖固定环。

`agent_audit_snapshot` 提供累计入环数、主动过滤数和覆盖数；关闭全部审计时均为0。过滤计数为独立原子变量，入环状态受审计锁保护，因此这是观测快照，不保证所有字段处于并发事件的同一事务切面。来源、取舍与原始机制差异见[研究与技术选型](研究与技术选型.md)。

## 8. 演示顺序与预期结果

在本仓库根目录运行：

```bash
make test-agent
```

程序依次完成内核边界测试、真实用户拒绝演示、Aegis 开启时的完整 Lab 5 用户负载、同目录 1→0→1 配置切换及默认演示。

专用演示的关键顺序：

1. 首进程代码和栈占 2 页，组上限 4 页。
2. 禁止 copyout，允许 copyin，输出 `aegis capability deny PASS`。
3. mmap 2 页后预算已满；额外 mmap 和 brk 被拒绝。
4. 解除 1 页后 brk 可以占用该预算，缩堆后 mmap 可以再次使用。
5. 输出 `aegis quota reuse PASS` 和 `aegis USER PASS`。
6. 满预算下访问更低的合法栈地址，扩栈失败，停止该用户程序。
7. 输出 `aegis group cleanup PASS`；导出拒绝和故障审计；随后 ticks 继续。

这说明内核能约束可控工作负载，不代表已执行大模型。其他复验入口为 `make test-lab5`、`make test-lab4`、`make test-lab3`。详细记录见 [AGENT_VALIDATION.md](AGENT_VALIDATION.md) 和 [LAB5_VALIDATION.md](LAB5_VALIDATION.md)。

## 9. 汇报时如何表达差异化

可以陈述：在课程内核上加入可关闭的组级资源抽象，在真实系统调用和内存增长路径实施页预算与服务权限，能够观察拒绝原因并验证失败回滚、预算复用和退出回收。

## 11. 对照实验与答辩细节

`make bench-agent` 分别构建 `AEGIS=0`、`AEGIS=1 AEGIS_AUDIT=0`、`AEGIS=1 AEGIS_AUDIT=1` 以及 `AEGIS=1 AEGIS_AUDIT=1 AEGIS_AUDIT_SUCCESS=0`。四个用户二进制逐字节一致。每种配置独立启动3次，每次先测31批brk查询（每批1024次调用），再测31批mmap/munmap往返（每批128对）。每批有预热，计时区间不进行串口输出。

指标为用户态读取time前后的差值除以批内操作数；先取每次启动的批均值中位数，再取三个启动中位数的中位数。map-cycle的一次操作包含两个syscall。报告同时保存三个启动中位数的范围、模式执行顺序、完整构建配置、编译器/QEMU版本、源码和镜像SHA-256以及串口日志。

原始数据和表格见[本轮QEMU微基准](benchmarks/agent/2026-10-23-selected/README.md)；[历史三配置数据](benchmarks/agent/2026-10-23/README.md)保留对应旧源码摘要。宿主调度、TCG和定时中断都会影响guest time，因此只能把结果描述为该配置下的微基准成本。成功调用负载有利于过滤方案，不能推断拒绝风暴的成本。每个样本是批均值，不能据此声称获得单次syscall的P95/P99，也不能推导真实Agent吞吐或实板性能。
