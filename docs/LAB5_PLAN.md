## 先统一规格，避免模板中的冲突

以下为已确认的差异，需要在第一份规格提交中明确处理：

| 项目 | 模板源码或旧教学内容 | 本次采用的规格与处理 |
| --- | --- | --- |
| 用户复制返回值 | `uvm_copyin/out/in_str` 仍为 void 空函数 | 改为 int，成功 0、失败 -1；逐页检查 V/U/R/W |
| mmap 返回值 | `uvm_mmap` 为 void；`sys_mmap` 注释写失败 -1 | 返回地址，失败 0；用户封装同步 |
| 用户未知调用 | 模板 syscall 会 panic，且先缩窄调用号 | 完整 64 位有界查表，失败返回 -1，内核继续 |
| 参数宽度 | `arg_uint32` 直接截断 | 服务先检查完整 64 位值及乘法溢出，再缩窄 |
| 节点耗尽 | 注释要求 panic | 返回 NULL，映射和进程链不变 |
| mmap 链含义 | PDF 部分图示使用空闲区模型 | 按 uvm 规格维护已分配区间，按地址排序；仅合并同权限相邻区间 |
| mmap 权限 | 现有节点缺少 perm 字段 | 增加权限字段，供合并及页表复制验证 |
| 页表销毁 | 模板先释放 trapframe | uvm 只释放用户页及页表页；trapframe 由进程单独释放，trampoline 共享 |
| 首进程归属 | 个人实现固定在 hart0 运行 | Lab 5 改为 boot_hartid 运行，ticks 与 UART 路由同步调整 |
| 平台构建 | 个人实现支持单 hart；Lab 5 模板限定 QEMU 双 hart | 默认课程验收采用双 hart；Lab 4 单 hart 基线留在 lab-4，不覆盖课程构建约束 |
| 首进程函数属性 | patch 中写 noreturn，模块签名是普通 void | 在本地规格中写清分配失败与故障回收后可返回主循环；不加与行为矛盾的属性 |
| 地址宏命名 | 规格用 PAGE_SIZE、USER_HEAP_BASE 等描述名，源码用 PGSIZE 等 | 在规格中给出与实际头文件一致的映射，避免引入两套冲突常量 |

ABI 按规格统一为编号 0–7：helloworld、copyin、copyout、copyinstr、brk、mmap、munmap、printf。只有 usertrap 对 ecall 的 epc 加 4；栈缺页成功后保留原 epc 重试。

`sys_printf` 的精确参数和返回值在助教规格中尚未展开。建议第一阶段定义为有长度上限的用户字符串输出，内容作为数据交给 `printf("%s", ...)`；不直接把用户字符串当作内核格式串。上限、是否包含 NUL、成功返回字节数等要先写入本地规格再实现。

## 实现顺序与阶段验收

每阶段先明确契约，再实现，再提交对应验收证据；不把所有功能堆在一次提交里。

### P0 / M0：完成可执行规格

工作：引入并补全 `spec/modules/uvm.yaml`、`syscall.yaml`、`spec/patches/lab5.yaml`，调整 design、process、usertrap、user、memory、toolchain、boot、console、trap 中受影响的契约。保留个人实现已经补全的有效约束。

必须写清：各函数的 pre/effects/post、失败返回、页面与节点所有权、零长度行为、地址上界、栈合法范围、mmap 自动选址、munmap 完整覆盖规则、销毁流程、TLB 失效责任。

验收：所有必做接口无空白契约；签名、syscall 编号、头文件与用户封装一致；将“待实现”和“已验证”区分。先单独提交规格，不宣称代码已完成。

### P0 / M1：接入平台与模块骨架，保持原功能

涉及：Makefile、common.mk、kernel.ld、boot、arch、PLIC/UART/timer、proc 类型及 syscall/uvm 模块入口。

工作：以个人 lab5 代码为基础逐项移植课程增量，保留已完成实现；不能用助教的空函数覆盖内存、锁、trap、进程与打印代码。引入 `PLATFORM=qemu/vf2`、隔离产物、VF2 Image 头、首次/次级入口和 boot_hartid。新模块以可编译的分步增量接入，保留 -Werror。

验收：QEMU 双 hart 仍能进入用户态、处理 timer/UART；内存自检、权限、用户故障回收、memmove、panic、无修改构建与配置变化重建均保留。课程要求拒绝非法 PLATFORM、QEMU 非双 hart，以及 vf2 的 run/debug。VF2 未填写硬件常量前的构建失败单独记录，不标为通过。

### P1 / M2：统一 syscall 与用户复制

涉及：`mem/uvm.c`、`syscall/*`、`trap/trap_user.c`、`user/*`。

工作：实现逐页转换与 copyin/copyout/copyinstr，再接固定 syscall 表及演示服务。内核缓冲区使用有界大小；copyin 的数组元素数量先校验，再计算字节数。跨页失败允许目标留下前缀，调用者不得将失败的字符串当作完整字符串。

验收：课程数组 1–5 往返和字符串示例通过；非对齐跨页、末位 NUL、缺 NUL、只读页写入、不可读页、无 U 位、trapframe/trampoline、零长度、地址溢出均覆盖；未知号及高位非零的长度返回失败，用户仍可发起下一次合法调用。

### P1 / M3：堆与自动栈增长

涉及：`uvm.c`、`sysfunc.c`、usertrap、进程初始化。

工作：brk 按字节记录堆顶，按页面管理映射；页内变化不多分配或多释放页面。堆不得进入 mmap 区。仅对用户 load/store 缺页且 fault 地址位于尚未映射的合法栈扩展范围时补页，一次补齐间隔中的所有页面；已有页面权限故障与 instruction fault 不视为扩栈。

验收：brk 查询、同值、页内、跨页、缩到初始值、上下界与溢出；一次跳过多页的栈访问、课程 4 页数组/递归示例；代码写入、零页访问、越界访问仍停止用户进程。对数据页和页表页的每个失败点注入 OOM，核对映射、堆顶/栈页数和空闲页数恢复。

### P1 / M4：节点池与 mmap/munmap

涉及：`mmap.c`、`uvm.c`、mem/proc 类型、sysfunc 和用户封装。

工作：实现带锁的全局节点池；节点从空闲池、临时操作、进程链之间唯一转移。mmap 支持自动首次适配和固定地址；检查对齐、长度、权限与重叠。munmap 先确认整个请求已映射，预留中段拆分所需节点，再裁剪/拆分/跨节点删除；含空洞或资源不足时整体不变。

验收：256 节点全部申请、耗尽、回收、复用和双 hart 并发；课程测试 4；同权限双侧合并、异权限不合并、首尾空洞、整段/前缀/后缀/中段/跨段解除、含空洞拒绝。失败后链、PTE、节点数和两类空闲物理页数一致。

### P1 / M5：页表复制、销毁与完整回收

涉及：`uvm_copy_pgtbl`、`uvm_destroy_pgtbl`、proc 资源清理。

工作：复制代码、heap、已分配 stack、mmap 的内容与权限到独立物理页；目标预先持有自己的特殊映射。失败撤销本次复制，保留目标原有特殊页。进程故障回收统一经过新的用户页表销毁逻辑，随后回收 trapframe 和 mmap 节点；删除旧的 code/stack 独立释放路径，避免重复释放。

验收：复制后逐页内容与权限一致，修改新页不影响旧页；每个分配失败点无资源泄漏，目标特殊映射不变。带动态 heap/stack/mmap 的进程故障后所有动态资源归还；trampoline 不被释放，trapframe 恰好归还一次，启动时预分配内核栈按现有所有权保留。

### P1 / M6：VF2 实板完成与最终验收

平台证据采集可在 M1 后进行；完整业务验收依赖 M2–M5。

工作：核对板型、有效 hart、timebase、RAM/保留区、UART 步长与 IRQ、PLIC S-context、PTE A/D 需求，将来源写入规格；完成 vf2 常量和镜像检查。现有 `../vf2-diagnostics/2026-10-13/处理记录.md` 可作为历史线索，不能替代本轮设备状态确认。

验收：两个平台不 clean 交替构建不串用产物；检查 Image 头、链接地址、BSS 与栈范围。实板以现有 OpenSBI/U-Boot 的 booti 加载，验证每核启动、UART、持续时钟、Sv39、用户态和任务 1–5；保存完整串口日志。QEMU 与宿主内存探针的成功不能代替实板通过。

本计划不操作开发板、不修改启动环境或固件。后续实测沿用已有固件和可恢复的文件加载流程；仅在已确认的设备与内存布局上启动镜像，不自动 saveenv 或刷写固件。

## 关键实现风险

1. **多页回滚不能只依赖单次 vm_mappages。** 它只回滚自身调用；外层连续多次成功后再失败，仍需回收此前新建的叶项、用户页和中间页表页。先设计事务记录及资源预留方式，不直接 freewalk 整个活动进程页表；不能只检查用户页计数而漏掉页表页。
2. **页表和 mmap 链必须一起提交。** 在物理页、页表路径和拆分节点准备完成前不发布元数据；回滚本身不再申请资源。
3. **硬件权限与 copy 权限都要检查。** 栈增长不能绕开代码只读保护，copy 不能通过恒等映射访问用户本不该访问的物理页。
4. **启动核变化影响测试。** 首进程、ticks、UART 接收和用户态中断探针必须使用同一个启动核归属，不继续硬编码 hart0；测试从启动输出识别归属。
5. **地址空间销毁前先停止使用。** 明确本地 TLB 刷新与物理页复用顺序。当前唯一用户地址空间只在一核使用，辅助核不共享运行它；不提前扩展为多进程远程 shootdown 框架。
6. **测试程序不能悄悄超出用户镜像一页限制。** 优先使用隔离场景镜像；若确需多代码页，先扩展规格、加载与清理，再单独验收，不能删除链接断言蒙混通过。
