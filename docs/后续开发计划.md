## M1 实施契约

新增内核内部 `proc_clone_resources(dst, src, pid)` 与 `proc_release_resources(p)`，复用已验证的用户页表复制。它只准备资源快照，不发布 cpu.proc，不设置可运行内核上下文，不新增 fork syscall。

- 调用者独占并稳定持有源、目标和组对象；源不能在另一 hart 上运行或修改。目标须全零、与源不同；未来进程锁负责满足这一条件。
- 目标独占自己的 trapframe、页表、用户数据页和 mmap 链；只共享 trampoline 和组策略对象。内核栈和调度上下文不复制，必须由 M2 初始化。
- 源有组时，按实际用户叶页数一次性预留子成员和全部数据页，成员和页数在同一组锁内检查；拒绝在物理分配前发生。源无组时目标保持普通进程。
- 预留期间的成员与页数包含正在构造的目标，策略收紧不能越过这些用量；共享策略使未来收紧同样作用于目标。
- 成功复制用户寄存器与用户 PC/SP，并将目标 a0 置 0；清除依赖当前 hart/内核栈的 trapframe 字段，由未来运行入口重填。
- 任何分配失败都释放全部目标资源和预留，目标恢复全零；源内容、映射、元数据及当前组用量不变。峰值和审计保留尝试历史，不承诺回滚。
- release 只处理已停止且未绑定当前 cpu.proc 的对象，先销毁地址空间，再退组、释放 trapframe/节点并清零；不释放预先映射的内核栈。
- 验收包括普通/入组复制、完整页内容及权限、互相修改独立、部分节点复制失败、每次物理分配失败、成员/页数拒绝、成功后策略收紧继承、重复清理和源最终回收。

M1 完成后也不能宣称已运行多进程或已实现 fork；M2/M3 的运行与调度实验才是该结论的依据。

## M2 实施契约（2026-10-23）

在课程尚未发布新规格时，以默认关闭的 `PROC_LIFECYCLE=1` 提供项目预研路径。默认0保持原课程0–7 ABI与单用户路径。开启后固定4个进程槽位，各持有独立、带空洞保护的预映射内核栈；仅实际启动hart调度，辅助hart不访问进程表。进程表修改、fork、wait、exit和切换均关中断且不持锁；本阶段只协作式切换，不在timer路径抢占。

扩展ABI编号8 fork、9 exit(status64)、10 wait(status64指针，0忽略)、11 yield、12 getpid。fork成功父返回正PID、子返回0，失败-1；PID单调增长、到有符号int上限拒绝而不回绕。wait回收任意一个直接子进程，返回PID；无子进程-1；无僵尸则阻塞；无效状态指针-1并保留退出记录供重试，跨页复制失败允许留下前缀。exit不返回，用户故障以-1结束；没有父进程的任务退出自动回收，活跃孤儿由内核继续调度并自动回收。没有exec、信号或完整POSIX语义。

状态：FREE → RUNNABLE → RUNNING → WAITING/RUNNABLE/ZOMBIE；只有CPU切回调度栈、清除cpu.proc后才能销毁退出进程的页表、trapframe与数据页。僵尸只保留PID/父子关系/状态，不占用户页与组预算；wait成功后槽位回到FREE。父进程退出使其子进程转为自动回收，避免悬挂父指针。

Aegis组允许集合在此构建中扩展到0–12，所有新增调用仍经过同一权限分派；默认启动组成员上限4，页预算64。fork沿用M1整批预留与失败回滚。exit另记生命周期事件，既有事件编号不变。默认课程构建仍只有8位允许集合与1成员启动组。

验收：真实用户fork返回值及父子独立页、yield交替、wait阻塞/先退出/坏指针重试、子故障、槽位耗尽与复用、父退出孤儿回收、真实fork逐物理分配失败回滚；退出后全部动态页/节点/组预算恢复，时钟/UART仍能前进。默认课程回归和三种审计配置兼容；实板只检查构建，不声称运行通过。


## M2 验收记录

已完成默认关闭的协作式生命周期，真实用户父子进程共享组约束并拥有独立地址空间和内核栈；wait、退出状态、故障、孤儿及槽位复用已验证。`make test-process`覆盖普通/全量审计/过滤审计/无审计四配置及三种真实fork策略拒绝；默认课程路径保持原ABI。浮点/向量现场尚不支持，FS/VS显式关闭。详细证据见 [PROCESS_VALIDATION.md](PROCESS_VALIDATION.md)。

下一阶段M3：先设计timer抢占时的上下文、锁和中断不变量，再用两个不主动yield的CPU密集任务验证前进，建立进程RR基线；组级调度仍排在其后。

## M3 实施契约（2026-10-23）

新增默认0的`PROC_PREEMPT`，1要求`PROC_LIFECYCLE=1`。只在来自用户态的timer中断、完成时钟更新并释放锁后考虑抢占；已有trampoline已保存全部用户整数现场及sepc。当前任务计一个用户timer样本，若还有其他RUNNABLE槽则转为RUNNABLE并切回CPU栈，按槽的循环顺序选择下一个任务。没有其他就绪任务时直接返回，不做自切换。

调度、等待、退出、fork及内核trap仍不被抢占：内核入口关中断，所有swtch均验证boot hart、SIE关闭、noff=0且当前槽状态合法。恢复用户现场时重写sepc/stvec/sstatus/satp；timer路径不推进用户PC。默认100ms名义周期沿用平台时钟，不保证每次dispatch得到完整新周期，不作为硬实时延迟保证。

验收使用同一用户镜像：两个子进程分别设置不同的寄存器模式，在没有ecall/yield的CPU循环中持续约1秒；两者必须在任意一方结束前都开始，均发生多次实际抢占，并在恢复后验证整数现场。关闭抢占作负对照时应串行完成，证明测试能区分协作运行与timer抢占。另在抢占开启时运行完整生命周期回归，检查wait、退出、预算及故障回收。

按任务汇报dispatch数、用户timer样本数、实际抢占数，用于功能验收；这些计数不是精确CPU时间、组公平性或性能收益。新增测试镜像`RR_TEST`与故障注入、课程测试/微基准互斥；默认课程ABI和协作式模式保留。


## M3 验收记录

`make test-rr`通过同一用户镜像的串行负对照与四种抢占配置，两个无yield任务在任意一方结束前均已启动，分别多次抢占并通过独有寄存器模式检查。`python3 tests/test_process.py --preempt`通过完整生命周期与策略拒绝回归。只抢占用户态，内核处理与锁临界区仍不可抢占，辅助hart不运行用户任务。证据见[RR_VALIDATION.md](RR_VALIDATION.md)。

下一阶段M4先明确组创建/成员归属的可信接口和组权重，再扩展槽位构造不等成员数对照，比较进程RR和组间选择；先定义测量窗口、CPU时间及等待指标，不直接将当前timer样本解释为公平份额。


## 当前开发方向（以本节为准）

按用户最新要求，以功能开发为主，只做必要的正确性检查，不主动安排性能对照、统计实验或论文式报告。保留此前历史记录，后续工作按实际功能依赖推进。

本轮接入：首进程管理组、用户态agentctl封装、指定组派生与目标预算回滚、组号失效处理、权重调整、空组删除、组间加权选择和组内轮转。新增`make build-aegis/run-aegis`统一配置入口；功能说明随代码维护。

后续优先：让实际用户任务使用这些接口，再按使用需要补齐配额收紧、审计读取和文件/工具权限。文件与exec相关能力等待对应课程模块，不提前堆叠实验材料。
